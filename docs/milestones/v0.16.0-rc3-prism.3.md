# v0.16.0-rc3-prism.3 — RTX 20/30/40/50 与默认关闭 MTP

以 **Experimental / 实验版 Pre-release** 公开发布，提供 Windows x64 预编译包、完整 UI、
CUDA 运行库、匹配源码和 SHA256 校验。Prism 基线仍为
`9a9394a895b96003ca842a6041cb28ac49a108f7`。

[公开下载](https://github.com/kvmem/kvmem-llama.cpp/releases/tag/v0.16.0-rc3-prism.3)。
该版本显示在主仓库的 Releases 页面，标签指向 Bonsai 分支的构建提交，未合并到 master。
预编译包仍对应 `e487b0ab26943186fb5ee9560bc153386d21e493`；草稿转为公开预发布不改变附件内容。

## 变化

- 增加 **SM75**，与 SM86/89/120a 一起编译，覆盖 RTX 20/30/40/50 系。
  20/30/40 系没有实机验证，不能将编译成功当作全部显卡的运行验收。
- **默认关闭 MTP**，默认选择原始 `Ternary-Bonsai-2-27B-PTQ1_0.gguf`。
  保持 128K 上下文、24K 检索预算、10K 生成预留、主 KV Q8、思考预算 4096。
- 手动 `-Mtp` 开启时，默认 MTP1 和 **F16 草稿 KV**。
  `-DraftTokens 2` 可用于代码场景；`-DraftKvType` 独立设置草稿 KV。
- 合入先前已验证的代码生成对照、F16 显存对照及长文 KV 诊断。
  KV 字节检查默认关闭，不增加日常推理开销。
- 包内构建元数据同步标记 `mtp_default=false`，避免与启动器默认配置矛盾。

## 启动

解压运行包，在其目录中运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-bonsai.ps1 -Model 'D:\models\Ternary-Bonsai-2-27B-PTQ1_0.gguf' -Gpu 0
```

然后访问 **http://127.0.0.1:18202/**。运行不需要 CUDA Toolkit、Python 或 Node.js。
需要兼容 NVIDIA 驱动、VC++ x64 运行库及 AVX2/FMA/F16C/BMI2 CPU。
模型文件需单独下载，见 [快速使用](../../scripts/windows/README-bonsai.md)。

## 历史性能参考

5060 Ti、Q4 MTP 头、主 KV Q8、草稿 KV F16、24K+10K、关闭思考：

| Python 代码输入 | MTP 关闭 | MTP1 | MTP2 |
|---|---:|---:|---:|
| 约 4K | 45.84 tok/s | 61.43 tok/s | 68.93 tok/s |
| 约 16K | 40.82 tok/s | 50.28 tok/s | 58.63 tok/s |
| 整卡峰值 | 7208 MiB | 7766 MiB | 7916 MiB |

这是加入 SM75 前的二进制测量，并非本次新包的完整性能复测。
两个编程任务的样本有限，输出 156–352 tokens，prefill 占主要时间；
MTP2 整次请求缩短约 9.5%/2.1%，不能套用 decode 增幅。
功能检查：拓扑排序通过，区间合并在所有模式下都有同一个边界错误。
详见 [代码测试](../bonsai-coding-mtp012-5060.md) 和
[F16 草稿 KV 对照](../bonsai-mtp1-f16-5060-comparison.md)。

## 已知限制

- 本版不宣称修复长文检索。历史 80K/128K 测试出现 1/3 召回，
  部分失败时三个答案块都已进入 KV 预算。增加固定前缀的一次成功实验不构成通用修复。
- 未验证连续生成 10K、20/30/40 系实机、视觉及所有工具调用场景。
- MTP 使用社区 r3 头，并非 Prism 官方头；不集成 DSpark，不支持 NVMe KV 外溢。
- 旧测试条件和新包验证分别记录；本次包的构建、架构、便携启动和 GPU 检查详见 `VALIDATION.json`。
